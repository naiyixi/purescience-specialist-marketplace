# PureScience 专家内容创作标准（AUTHORING STANDARDS）

> 适用范围：`specials/<id>/` 下所有专家包内容 —— specialist.json、SKILL.md、references/、scripts/。
> 铁律：方法可借鉴，**文本零复制**；本仓库与 App 仓库零品牌指纹（见文末 §6）。

## 1. 命名规范（表面层全中文医学命名）

| 对象 | 规范 | 正例 | 反例 |
|---|---|---|---|
| 专家显示名 | `医学方法/对象 + 职能 + 专家`，≤18 汉字 | 真实世界证据研究专家 | RWE Specialist / 证据大师 |
| 专家 slug | 英文小写 kebab（代码/市场 id，稳定不可变） | `rwe-research-specialist` | RWE_Specialist_v2 |
| 技能显示名 | 中文动词短语，≤12 汉字，不造词 | 不确定度与单位审计 | UncertaintyKit |
| 技能 slug | 小写字母/数字/连字符 | `uncertainty-units-audit` | — |
| 连接器 | 沿用 App 内已中文化 catalog 名称 | 文献图谱 / PubMed | — |
| prompt 章节 | 全中文，统一十二段式（见模板文档） | 诚实运行守则 | Runtime Contract |
| 术语统一 | 专家/技能/连接器/项目/产物/审阅/证据溯源 | 一律用 App 既有词汇 | 引入"专才/组件"等新词 |

**slug 一旦发布不可改名**（市场安装记录、会话绑定、更新链都依赖 id）；显示名可改。

## 2. 文本铁律

1. **零复制**：不得逐句翻译、改写、同构复刻外部专家文本；结构借鉴须用自己的章法与措辞重新表达。
2. **中文原创**：正文默认简体中文；领域必需英文术语（GCP/ICH/CONSORT/STROBE/STREGA 等国际标准名）以原文夹注，属正当医学语言。
3. **自洽产品词**：prompt 中引用 App 自家概念 —— 项目、产物、审阅、证据溯源、连接器 —— 让专家像为本运行时撰写。
4. **无 AI 腔**：不写"作为一个…专家"式开场套话；直接陈述职责、边界与工作准则。
5. 包内任何文件不得出现第三方产品名、厂商名、其仓库/作者身份（含本地 gitignored 文件，同 App 仓库纪律）。

## 3. 质量门槛（发布前必须全部满足）

| 维度 | 门槛 |
|---|---|
| system_prompt 规模 | 1.5 万–2.5 万字符（约 8–15K token），十二段齐全 |
| 完成定义 | 必须含：诚实运行守则、领域闸门（编号化）、完成定义、交付清单、终检 |
| 技能包 | 每专家 3–6 个技能；每技能 = SKILL.md（中文触发词工程）+ ≥1 references 或 scripts（可运行/可审计），不得空壳 |
| 公共技能复用 | 公共基础包优先复用，不复制进多个专家 |
| 连接器 | 声明白名单（仅本专家会话可用），连接器 id 必须存在于 App catalog |
| 验收题 | 每专家 ≥3 条验收题：1 条正常流程、1 条阻断场景（缺输入必须 blocked 且不编数）、1 条边界（拒绝诊断/处方类请求） |
| 收尾协议 | 一律以「通过 / 有条件 / 阻断」+ 理由收尾 |

## 4. 十二段式 prompt 骨架（顺序固定）

1. 身份与职责（1 段，含一句话边界声明）
2. 诚实运行守则（反幻觉铁律：模式选择/证据账本/来源标签/量纲核查/未确认不推定/空想数值禁令）
3. 能力路由（技能白名单 + 每技能何时用/何时不用）
4. 数据源政策（连接器白名单、检索留痕、版本记录）
5. 领域第一性原理（3–6 条核心原理，可推导工作方法）
6. 工作方法（分层决策：概念估算 → 标准工具 → 深度计算 → 实测）
7. 严谨性清单（对照/混杂/自反性提问）
8. 故障手册（特征性失败模式 → 诊断与处理）
9. 完成定义（验收标准清单）
10. 领域闸门（编号 G1…；每条 = 禁令或必要条件；附"闸门失败如何处理"）
11. 交付清单（8 项：范围/账本/流程/参数表/质检矩阵/结果与阻塞/复现清单/交接）
12. 终检（输出前逐项自检，末行输出 通过/有条件/阻断 + 原因）

> 与任何外部实现刻意不同章、不同名、不同合并方式 —— 这是原创性与零指纹的工程保证。

## 5. 技能包结构

```
skills/<skill-id>/
  SKILL.md        frontmatter: name(与目录一致)/description(中文触发词：何时用/何时不用/边界/反例)/license
  references/     按需加载的深读材料（触发条件写在 SKILL.md 内）
  scripts/        可执行工具（带参数校验与失败留痕），导入预览不执行
```
- description 是技能路由的关键：写明触发场景 + **不适用场景** + 显式反例。
- references 控制在 5 个以内；scripts 须能独立运行且不写死网络依赖。
- 引用其他技能时只写交接语义（handoff），不复制内容。

## 6. 零品牌指纹（提交与发布纪律）

1. 提交信息、文件内容、目录名、git 历史不得含第三方产品/厂商/仓库名与"上游"等指代。
2. 提交前自检：`grep -rniE '品牌词表' <改动>`；市场仓库同样安装 commit-msg 钩子。
3. 本地研究素材（参考包/参考 prompt）只放 `~` 目录，**永不进入任何 git 仓库**。
4. 包 LICENSE 仅用自己声明的许可证；不得粘贴第三方许可文本（含其仓库名/作者名的部分）。
