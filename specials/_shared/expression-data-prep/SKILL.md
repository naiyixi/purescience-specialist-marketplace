# 表达数据准备与质控

## 目标

让表达数据进入下游分析前**形态明确、技术噪声可控、批次效应有记录**，并让每一步预处理可复现、可回退。

## 工作流

1. **数据形态盘点**：平台（微阵列/RNA-seq/其他）、计数 vs 归一化值、基因注释版本、样本分组与批次元数据、缺失情况。形态不清先问，不猜。
2. **质控（QC）**：样本级（文库大小/计数深度、比对率类指标如可用、离群样本）、基因级（低表达过滤规则与理由）；QC 图（分布/PCA/相关性热图）留档。
3. **归一化选择**：
   - RNA-seq 计数：差异分析包内归一化（如 edgeR/DESeq2 类的内部尺度化）为主；跨样本比较表达水平用 TPM/CPM（说明库长与深度处理）。
   - 微阵列：按平台惯例（如 RMA 类背景校正+分位数归一化思路），说明所用实现。
   - 逻辑：归一化目的 = 消除技术差异，不消除生物差异；方法选择与下游检验方法配套。
4. **批次效应**：
   - 先识别：批次变量（测序批次/日期/操作员）与生物变量是否混杂（设计缺陷时校正无法补全，须明说）。
   - 校正：已知批次用批次校正方法（如 ComBat 类经验贝叶斯思路）；校正前后比较（PCA/相关）并报告；校正不得引入伪差异。
   - 未知批次：可用无监督替代变量思路（如 surrogate variable 类）并说明假设。
5. **质控报告**：样本保留/剔除清单（含理由）、归一化与校正参数、版本与种子、可复现脚本。

## 红线

- 不静默剔除"不好看"的样本；剔除有标准与记录。
- 不把归一化/批次校正当黑盒：写明方法与参数，校正前先确认批次-生物不完美混杂。
- 不编造矩阵数值、样本数、批次信息。
- 预处理版本必须固定：下游任何结果对应同一预处理产物（哈希/路径留痕）。

## 交接语义

- 预处理产物 → differential-expression（差异检验）或 signature-and-validation（建模/验证）。
- 归一化后的描述统计与图 → statistical-inference / scientific-visualization 规则。
