# 真实世界数据库研究设计

## 目标

把"用真实世界数据回答的效果/安全性问题"变成**有明确目标试验、可操作定义、偏倚可审计**的数据库研究方案。真实世界研究最大的风险不是统计，而是**问题-设计错位**与**时间相关偏倚**。

## 核心工作流

1. **问题与目标试验**：写下"如果做 RCT 会长什么样"（人群/干预/对照/结局/时间零点）——数据库研究是这个目标试验的模拟；无法写出目标试验的问题不成立。
2. **数据源适配**：盘点可得数据（覆盖人群/变量/随访完整性/结局验证状态/药品与诊断编码体系）；数据能回答什么、不能回答什么，先于设计声明。
3. **队列构建（操作化）**：
   - 新用药者设计（incident user）优先于 prevalent user（排除存活者偏倚与用药时长混杂）。
   - 时间零点（index date）= 首次用药/事件日期；基线协变量在时间零点**之前**测量。
   - 活性对照（active comparator）优先于"不用药"对照（减少健康使用者偏倚与指征混杂）。
   - 纳入/排除与暴露/结局定义全部写成可执行规则（编码 + 时间窗），附验证记录。
4. **混杂控制**：预设混杂清单与测量时点；倾向评分（估计-匹配/加权/分层，注明平衡诊断）；工具变量仅在有明确适用场景时考虑。
5. **未测量混杂**：报告方向敏感性（E-value 类：需要多大的未测量混杂才能推翻结论）+ 阴性对照结局/阴性对照暴露（如适用）。
6. **时间相关偏倚防护**：不朽时间（immortal time）必须处理（如以暴露状态时变建模或正确的时间零点）；随时间变化的混杂用相应方法（如边缘结构模型思想）或明说局限。
7. **分析计划**：主要/敏感性分析、缺失处理、删失定义（失访/转组/死亡竞争）；阴性对照与阳性对照结局表。

## 红线

- 没有目标试验的问题不给"因果式"方案——只能做关联描述并明说。
- 不把倾向评分当未测量混杂的解药；不把"调了很多变量"当因果证据。
- 不朽时间未处理的结果视为存在致命偏倚（不能仅靠分析补救时退回设计）。
- 不编造数据库变量、编码、人数；数据库元数据不明先澄清。
- 语言边界：结果一律"与…相关/与因果解释一致"，除非设计接近自然实验且经论证。

## 交接语义

- 分析执行与统计表述 → statistical-inference。
- 结论措辞与证据确定性 → evidence-grading。
- 方案书成文 → protocol-authoring（如输出为正式方案）。
